## 1. 지금 어디까지 와 있나

| 영역 | 상태 |
|------|------|
| 생성 | Gemini 3.6 Flash로 월간 식단 생성 → 코드 검증 → 최대 2회 자동 재생성 |
| 규칙 | 조건 6종(횟수·끼니·요일·간격·카테고리·서술형) + 서술형 문장 자동 해석 |
| 데이터 | 메뉴 풀, 일시정지, **과거 식단 기록**(직접 입력 / 엑셀 가져오기 / 표 저장) |
| 출력 | 배달용·주방용 엑셀 2서식, 텍스트, 인쇄, 복사 |
| 배포 | PyInstaller 단일 exe, GitHub 프라이빗 레포로 JSON 동기화 |

한 달치를 "만들어서 출력"하는 데까지는 완성됐다. 고도화의 방향은 세 갈래다 —
**깨지지 않게(품질) · 덜 쓰고 더 맞게(생성 효율) · 출력 다음까지(실무 확장)**.

## 2. 지금 비어 있는 곳

| # | 빈 곳 | 왜 문제인가 | 근거 |
|---|-------|-------------|------|
| 1 | **테스트 0개** | 규칙이 프롬프트(`SYSTEM_INSTRUCTION`)와 코드(`validate_menu`) 두 곳에 나뉘어 있어, 한쪽만 고치면 아무도 모르게 어긋난다. 엑셀 서식 수치도 손대면 글자가 잘리는데 잡아줄 게 없다 | 저장소에 `test_*.py` 없음 |
| 2 | **재생성이 월 통째로** | 위반 1건에도 62줄 전부를 다시 만든다. 토큰·시간 낭비이고, 다시 만든 결과가 또 다른 규칙을 어길 확률도 같이 커진다 | `menu_planner.generate_validated_menu` |
| 3 | **API 없으면 정지** | 무료 키 한도(429)나 모델 은퇴에 대비해 모델 대체는 있지만, 다 막히면 아무것도 못 만든다. 과거 기록이 쌓여도 그걸로 직접 편성하는 로컬 엔진이 없다 | `MODEL_FALLBACKS`만 존재 |
| 4 | **위반이 눈에 안 보임** | 위반 목록이 팝업 글로만 뜬다. 표의 어느 칸이 문제인지 사람이 찾아야 한다 | `gui.MenuPlannerApp._on_done` |
| 5 | **되돌리기·자동저장 없음** | 표를 고치다 창을 닫으면 그대로 날아간다 | `_flush_cells`만 있고 이력 없음 |
| 6 | **API 키 평문** | `config.json`에 그대로 적힌다(파일은 gitignore로 막아 뒀을 뿐) | `app_config.py` 상단 주석 |
| 7 | **공휴일 하드코딩** | 2026년만 들어 있어 2027년엔 공휴일을 모른다 | `KR_HOLIDAYS_2026` |
| 8 | **식단표에서 끝남** | 짠 다음의 **발주·원가**는 여전히 손으로 한다. 실무 시간의 절반이 여기 있다 | 해당 기능 없음 |
| 9 | **공유가 파일 전달** | 카톡으로 보내려면 사람이 캡처한다. 거래처가 열어 볼 링크가 없다 | PDF·웹 뷰 없음 |

## 3. 단계별 계획

### 1단계 — 기반 다지기 (8월)

뒤에 뭘 얹어도 안 깨지게 만드는 단계. **여기를 건너뛰면 2단계에서 되돌아온다.**

1. **회귀 테스트 하네스** `pytest` — `validate_menu` / `conditions.parse_text` /
   엑셀 서식 수치 / `history` 저장 왕복을 고정
2. **규칙 위반 부분 재생성** — 위반된 날짜만 다시 요청 (토큰·시간 대폭 절감)
3. **미리보기 위반 하이라이트** — 문제 셀을 빨갛게 + 사유 표시
4. **자동 저장과 되돌리기** — 편집 중 임시 저장, `Ctrl+Z`
5. **API 키 암호화**(Windows DPAPI) · **공휴일 자동 계산**

### 2단계 — 실무 가치 (9~10월)

식단표를 '출력물'에서 '운영 도구'로 넓히는 단계.

1. **메뉴 단가·원가 관리** — 일/월 예상 원가, 예산 초과 경고
   (생선류 월 4회 같은 제한이 사실 단가 문제라 조건과도 이어진다)
2. **주간 발주서 자동 생성** — 식자재 소요량 집계 → 발주서 엑셀 ⭐ 실무 절감 최대
3. **과거 데이터 오프라인 편성기** — 기록 + 규칙만으로 로컬 편성.
   AI 없이도 돌아가는 안전망이자, 기록을 쌓는 이유의 완성
4. **PDF·이미지 내보내기** — 카톡 전송용
5. **잔반·인기 피드백** — 그날 반응을 한 번 클릭으로 남겨 다음 달 가중치로

### 3단계 — 확장 (11~12월)

1. **거래처 열람용 웹 뷰** — 소방서가 링크로 이번 달 식단 확인
2. **다지점·다거래처 식단 분리**
3. **영양·알레르기 표기**
4. **자동 업데이트 배포**

## 5. 먼저 할 세 가지 — 착수 설계

계획을 '읽는 문서'가 아니라 '내일 시작할 수 있는 것'으로 내려놓는다.

### 5-1. 회귀 테스트 하네스 — ✅ 완료 (2026-07-28)

```
tests/
  conftest.py        # app_config.config_dir 를 tmp_path 로 갈아끼움 = 실 데이터 안 건드림
  helpers.py         # 식단표 텍스트 조립, 시트에서 셀 찾기
  test_validate.py   # 20건 — 6개 아님 / 김치류 2개 / 4일 간격 / 달 경계 / 과거메뉴만
  test_conditions.py # 19건 — parse_text 문장별 + 조사 처리 회귀
  test_exporters.py  # 11건 — 열 너비 31.38·25.13, wrap_text, 행 높이 비례
  test_history.py    # 21건 — 저장/교체/덮어쓰기, 엑셀 왕복, recent_tail 상대일
  test_store.py      # 11건 — 일시정지, 충돌 점검, 기록→풀 채우기
```

**82건 / 약 1.3초.** `pytest` 로 실행, `requirements-dev.txt` 로 설치.

- 핵심 장치는 `conftest.isolated_config`(autouse) — 이게 없으면 테스트가 실제
  `menu_pool.json`·`history.json` 을 덮어쓴다. 새 테스트 파일에도 자동으로 걸린다.
- 잠근 회귀 지점: 엑셀 열 너비와 `wrap_text=True`(줄이면 인쇄물 글자가 잘림),
  `_split_menu` 의 조사 처리(`이/가` 를 떼면 ‘고등어구이 → 고등어구’),
  `WRAP_SLACK`(없으면 7글자 메뉴명이 두 줄로 잡혀 행이 커짐),
  과거 기록의 교체 저장 vs 덮어쓰기 구분.
- CI는 `test`(ubuntu) → `build`(windows) 순서. **테스트가 깨지면 exe가 안 나온다.**

### 5-2. 규칙 위반 부분 재생성

지금 `generate_validated_menu` 는 위반 1건에도 한 달 전체를 다시 요청한다.

```
현재  위반 발견 → 62줄 전부 재생성 → 다시 검증 (최대 2회)
개선  위반 발견 → 문제된 날짜만 재생성 → 그 줄만 갈아끼움 → 다시 검증
```

- `validate_menu` 는 지금 문자열 목록을 준다. **반환 타입을 바꾸지 말고**
  `(날짜, 끼니, 사유)` 구조 목록을 하나 더 내보내는 쪽이 안전하다
  (GUI·CLI 양쪽이 문자열 목록을 그대로 쓰고 있다).
- 재요청 프롬프트: "아래 날짜만 다시 지어라 + 나머지 날짜는 이렇게 확정됐다(중복 판단용)".
- 돌아온 줄만 원문에 치환 → 재검증.
- **안전장치**: 부분 재생성이 2회 실패하면 지금처럼 전체 재생성으로 승격.
- 기대: 보통 62줄 → 1~5줄. 토큰·시간이 줄고, 이미 맞은 날짜를 다시 헝클지 않으니 통과율도 오른다.

### 5-3. 주간 발주서 자동 생성

한 번에 완성하려 하지 말고 **쓸모가 바로 생기는 순서로** 쪼갠다.

| 차수 | 필요한 데이터 | 나오는 것 |
|------|---------------|-----------|
| 1차 | 없음 (지금 데이터로 가능) | "이번 주 제육볶음 2회, 미역국 3회" 메뉴별 횟수표 |
| 2차 | 메뉴별 주재료 1~3개 (`제육볶음 = 돼지앞다리`) | 재료별 등장 횟수 집계 |
| 3차 | 1인분 수량 + 예상 식수 | 실제 발주 수량이 찍힌 발주서 |

- 1차는 코드 며칠이면 되고 그것만으로도 손 집계를 대체한다.
- 재료 매핑은 `menu_pool.json` 의 메뉴 항목에 필드를 더하는 방식이 자연스럽다
  (일시정지·조건이 이미 이름 기준으로 도는 구조라 이름을 키로 쓰면 된다).
- 출력은 `exporters.py` 에 시트 하나 추가 — 기존 서식 상수를 건드리지 않는다.

### Jira 가져오는 법

`설정 → 시스템 → 외부 프로젝트 가져오기 → CSV` 에서 `docs/jira_import.csv` 업로드.
필드 매핑은 헤더 이름 그대로 잡으면 된다
(`Issue Type` / `Summary` / `Description` / `Priority` / `Labels` / `Story Points` /
`Epic Name` / `Epic Link`). Epic 3줄이 먼저 만들어지고 Story 15개가 `Epic Link`로 붙는다.

> Jira MCP를 세션에 연결하면 CSV 없이 이슈를 직접 생성·갱신할 수도 있다.
> GitHub는 이미 동기화에 쓰고 있으므로, Jira 대신 **GitHub Issues + Projects**로
> 가는 선택지도 있다(레포가 이미 있으니 추가 비용이 없다).
